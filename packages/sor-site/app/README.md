# `app` — the runtime site shell

> **This is a CONTRIBUTOR document of the vsor framework repository, not of your
> project.** npm always packs a README, so this file travels inside the shell
> tarball and lands under `.vsor/site-runtime/` — where every repo-relative path
> it names (`specs/`, `../e2e/`, `fixtures/`) refers to the framework repo and
> not to anything beside your corpus. Nothing here is a file you edit; the seams
> you *do* own are documented in your project's own `AGENTS.md`.

This directory is `ag2/apps/learn-app` at `d764f334`, forked wholesale and then
emptied of its product layer. It is not an extraction and not a re-write: the
copy came across first, and everything the negative contract in
`specs/sor-site/surface/spec.md` excludes was deleted from the working copy
afterwards. That order is the point — fidelity is a property of the copy, not
something re-derived component by component.

## Layout

```
app/
  docusaurus.config.ts   identity + pipeline; every product key deleted
  sidebars.ts            one autogenerated sidebar over the corpus tree
  src/css/               upstream's design system: tokens, doc typography, sidebar
  src/theme/             swizzles: Navbar, Footer, Root, DocItem/Content, Landing
  src/components/        the kept primitives + the three shadcn parts they use
  static/img/favicon.svg the only shipped asset
```

The corpus is **`../knowledge`**, a sibling directory — the same relationship
the scaffold, the built runtime and the e2e harness all use. Override it with
`VSOR_KNOWLEDGE_DIR`; override the identity with `VSOR_SITE_TITLE`,
`VSOR_SITE_TAGLINE`, `VSOR_SITE_URL`, `VSOR_BASE_URL`.

## Building it locally

```sh
cp -r ../../../fixtures/tiny ../knowledge   # a real directory, see below
npm run build --workspace app
npx docusaurus serve --dir build            # from this directory
```

**`../knowledge` must be a real directory, not a symlink.** Docusaurus's MDX
loader decides a file is a doc by comparing its path against the configured
content path; through a symlink the resolved real path does not match, no
`metadata` export is attached, and every doc page dies in SSG with
`Cannot read properties of undefined (reading 'id')`. Found live 2026-08-14.

Serve it with a server that resolves extension-less routes (`docusaurus serve`
does; `python3 -m http.server` does not). Opening `/docs/x.html` directly makes
the client router miss the route, hydrate a not-found page over a doc page, and
log a React #418 hydration error that has nothing to do with this code.

## What this shell may not contain

The negative contract is `specs/sor-site/surface/spec.md`, and the machine-
readable form of it is `../e2e/tests/exclusions.json`. Both the source tier and
the built-bundle tier scan for the excluded identifiers, so this source
deliberately does not spell them out even in comments — a comment naming an
excluded component fails the same test the component would.
