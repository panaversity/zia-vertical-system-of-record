# v0 — what ships, how it is proven, what is deferred

The contract v0 must satisfy. Read with `AGENTS.md` (how we build) and `docs/status.md` (where we are).

> **This document deliberately does not decide mechanisms.** Field names, file formats and interfaces
> get decided while building, against real code. §7 lists what is being held open on purpose.

---

## 1. What v0 is

> **`vsor init` → put markdown in a folder → both surfaces serve it, and it is honest about what it
> does not know.**

Governance **level 0 only**: everything ingested, nothing declared. That single scope cut removes an
entire package from v0 — `sor-governance` is not needed until level 1, because a level-0 project has
no `governance/` directory at all.

**One skill only: `add-sources`.** It is the one the five-minute claim actually rests on.

---

## 2. Structure

Six packages. Four are extracted from upstream, one is new, one is the entry point.

| Package | Origin | Job in v0 |
| :--- | :--- | :--- |
| `ziavsor` | **new** | the CLI: `init`, `build`, `serve` — the only thing a user installs |
| `sor-platform` | extracted | db, config, contracts |
| `sor-gateway-kit` | extracted | fail-closed auth, serve loop |
| `sor-content` | extracted | ingest · chunk · embed · retrieve · abstain · generations |
| `sor-site` | extracted | the website surface |
| `sor-evals` | extracted | the proof (§4) |

Deferred out of v0 entirely: `sor-governance` (needs level 1), `sor-curriculum` (education-specific).

**`templates/` and `fixtures/` are both CI-tested artifacts, not sample text.** Astro's `examples/`
*are* `create-astro`'s templates; eve's `e2e/fixtures/` are ten runnable packages with their own CI
job. A scaffold generated from files nobody runs rots between releases and the first-run experience
breaks silently — the worst failure a framework can have.

### What the scaffold writes

The strongest single finding in the release research. **eve's scaffold writes nine files** —
`agent.ts` (four lines), `instructions.md` (three lines), a channel, `package.json`, `tsconfig.json`,
two ignore files, `AGENTS.md`, `CLAUDE.md`. It creates **none** of `tools/`, `skills/`, `evals/`,
`subagents/`, `schedules/`, `connections/` — six of the directories its own docs lead with. Its
documentation says why: *"Start with only instructions.md and agent.ts. Add the other folders when the
agent needs them."*

> **Empty scaffolded directories are worse than absent ones — they are unanswered questions sitting in
> the user's repo.** dbt's `init` is the cautionary case: it made four empty directories and no example
> model, so the generated project compiled nothing and taught nothing.

So `vsor init` writes: `instance.md`, `knowledge/` **with one real example document**, `AGENTS.md`,
`.gitignore`, the run scripts, and a git repo. No `governance/`, no `evals/`, no `reflexes/`.

Two rules from the same research, both cheap and both preventing a known failure:

- **Refuse to clobber**, and support adding to an existing project (`init .` writes only the subset
  that belongs to the framework).
- **Pin the runtime contract from a single value**, so a scaffold can never install one release while
  declaring another's requirements.

### The escape hatch

`create-react-app` shipped `eject` in 0.1.0 — the deferral was made *safe* rather than hidden, and
that is the strongest trust move available to a v0. **Ours is structural and already decided:** the
project is scaffolded into the user's own repo with the runtime vendored. If they outgrow the
framework they keep everything and owe us nothing. Say so in the README.

## 3. Tests

Copied from upstream, which measures **1,021 tests in ~12 seconds** across ~21k lines. The design is
worth taking whole.

| Tier | Selected by | May touch | Runs in CI |
| :--- | :--- | :--- | :--- |
| **Unit** | `packages/<pkg>/tests/test_*.py`; `_pure` suffix where explicitly pure | process memory + `tmp_path`. No sockets, no DB, no subprocess | ✅ |
| **Boundary** | `tests/test_boundaries.py` | reads source, **parses with `ast`, never imports** | ✅ |
| **Composition smoke** | `tests/test_*_smoke.py` | the real composition root, with a fake pool that *raises if touched* | ✅ |
| **Scaffold** | one job | runs `vsor init` and builds the output | ✅ |
| **Database** | module-level `skipif` on an env pair | a disposable local Postgres | ❌ opt-in |
| **Eval** | console scripts, not pytest | live provider | ❌ (§4) |

Four details that carry most of the value:

**The tier is defined by what a module does *not* do, not by a marker.** Everything not env-gated is
unit by default. Filenames are not selectors — upstream has `test_db_*.py` files that are pure fakes.

**One pytest invocation per package, in that package's own resolved environment.** Upstream's CI
comment states the reason: *"a member's tests physically cannot import a package it doesn't depend on —
the same isolation the boundary test asserts statically."* The workspace layout enforces layering for
free.

**I/O seams are replaced by hand-written fakes in the test file itself** — a `_FakePool` whose
`connection()` raises `AssertionError("the pool must not be touched during composition")`. No mocking
framework, no shared conftest.

**Async is per-package and deliberate.** Where `pytest-asyncio` is absent, tests call `asyncio.run()`
inside sync functions on purpose — upstream records why: *"an `@pytest.mark.asyncio` here would be
collected, never awaited, and PASS vacuously."*

**Boundary tests belong in v0 even though the codebase is small.** They cost a few hundred `ast.parse`
calls, they run in the ordinary gate, and they are what stops the layering decaying while it is still
cheap to hold.

## 4. Evals

Tests prove the code does what it says. **Evals prove the knowledge system behaves correctly** — and
that is a different thing, with a different failure mode.

Three classes, and being explicit about which one gates is the whole design:

| Class | Pins content identity? | Gates? |
| :--- | :--- | :--- |
| **Behavioural** — abstains on out-of-corpus questions; every citation resolves to a real document; never serves a generation that is not published | No | ✅ **gates** |
| **Relevance** — a known question retrieves the expected document | Yes, by slug | reported, **not gating** |
| **Correctness** — externally authored: this answer must still say $500,000 | Yes, by content | a **ratchet**: baseline may only grow. Empty at v0 |

**Why relevance must not gate.** Upstream's gold cases are generated *from the corpus being tested* —
the generator prompt is literally *"write one question which the following passage answers."* A wrong
rule therefore generates a gold question whose "correct" answer is the wrong rule, and the gate
certifies the defect. The failure mode is that everything goes green.

### The v0 gold set

Against `fixtures/tiny/`: roughly **10 in-corpus questions** and **5 out-of-corpus probes**. Row
schema follows upstream: `{q, expect, source, kind}` with optional `also_ok`.

The out-of-corpus probes matter more than the in-corpus ones, and upstream's are far-domain ("best
pizza place near me"). **Ours must include scope-adjacent near-misses** — the plausible-sounding
question the corpus does not actually cover — because that is the case abstention exists for and the
one a far-domain probe never exercises.

### The experiment v0 must run

**Can a usable abstention floor be derived from a ten-file corpus?** Upstream's floor took 416 gold
queries plus 38 probes to land on a number. It is entirely possible that ten files yield no separating
threshold.

Level 0 therefore ships with the gate **off** (`vector_floor: null`), and `/health` saying so. If the
experiment shows a floor is underivable at that size, the honest default may be a conservative fixed
floor plus an *uncalibrated* badge. **Recording that result is a v0 deliverable** — it is the promise
the market position rests on, and right now nobody knows the answer.

## 5. Shippable

Drawn from what real first releases actually contained.

- [ ] **Installable from a registry** with a pinnable version — not a git clone.
- [ ] **README in the proven order**: one sentence on what it is · the file tree with one comment per
      line, *before any prose* · the one-line quickstart · a complete minimal example that produces
      visible output · links to docs · the support channel · licence · the stability statement.
- [ ] **Docs shipped inside the package**, so an agent working in a user's repo reads ground truth
      offline with no network call. One line in the package manifest; disproportionate effect.
- [ ] **A scaffold that runs on the very next command with zero edits.** If the user must fill in a
      value before anything works, the scaffold has failed.
- [ ] **CI green**: lint · typecheck · unit · boundary · composition smoke · *scaffold builds*.
- [ ] **`LICENSE`, `CONTRIBUTING.md`, `SECURITY.md`, `CODE_OF_CONDUCT.md`** as real files.
- [ ] **`CHANGELOG` with breaking changes described in prose**, from release one.
- [ ] **A version number and one sentence saying what it means.** The number alone is not a stability
      signal.

### Versioning

The evidence contradicts the intuition: **almost nobody announces at 0.1.0.** eve announced at
**0.11.4** after ~40 prior publishes including twenty beta prereleases. Astro announced at 0.12.7.
Docusaurus announced at 1.0 — but only after six months of public alphas *and* already powering real
sites.

> **The number reflects how many times you have already broken it, not marketing.** Announcing at
> 0.11.4 reads as *"we already found and fixed eleven rounds of problems in public."* Announcing 1.0.0
> with no alpha series and no heavy internal usage is the move that costs trust.

**Publish 0.1.0 quietly. Let real usage move the number. Announce at whatever it has reached.**

State the 0.x contract explicitly, because SemVer's 0.x rules are widely misread: **minor may break,
patch does not.** Pair it with a 1.0 *condition*, not a date.

### Saying what is not ready, without losing trust

Four moves, present in every strong launch:

1. **Name it in the primary artifact, not a FAQ — and use the identical sentence everywhere.** eve's
   beta paragraph is verbatim the same in its README and at the top of its docs. One sentence, two
   places, zero drift.
2. **Bind it to something falsifiable.** "APIs may change" is noise; eve links an actual legal beta
   agreement.
3. **Say what you will keep.** The escape hatch (§2), shipped, not promised.
4. **Show real usage in the same breath.** Dogfooding evidence is what makes "beta" read as *early*
   rather than *unfinished*.

## 6. Explicitly deferred

Named as choices, with the cost acknowledged rather than argued away — that is how CRA deferred
testing and kept its credibility.

- **Governance levels 1–4.** v0 is level 0.
- **Five of six skills.** `add-sources` only.
- **Deployment targets beyond local.** Ship the one you actually run; do not fake breadth.
- **The customer-overlay mechanism**, which has no schema support today anyway (`corpus_id` is absent
  from all five content tables).
- **Brand genericization** and the second vertical.
- **Migration tooling and backward compatibility.** That is what 0.x is *for*.
- **Performance guarantees, benchmarks, SLAs.** Absent from every launch surveyed.
- **Governance process, RFCs, a dated roadmap.** These arrive when contributors do.
- **Safe-by-default enterprise behaviour.** Name the sharp edges precisely on one page and assign
  them, as eve does — that is more credible than a vague "secure by default" claim.

## 7. Held open on purpose

Decided while building, against real code — not now, from a document.

| Held open | Decide when |
| :--- | :--- |
| The exact fields, format and name of the build record | writing `build`, once there is something to record |
| Whether `git rev-parse HEAD:knowledge` is the right corpus identity | the first time a rebuild must be detected |
| The chunking parameters for a non-curriculum corpus | the first non-book corpus is ingested |
| Whether the site and the ingest share one build or two | wiring `sor-site`, where the seam becomes visible |
| The CLI's internal command structure | after `init`, `build`, `serve` exist and their shape is known |
| Whether level 0 abstention uses a fixed floor or none | after the §4 experiment reports |

**The rule:** if a decision can only be made well with code in front of you, it is not a v0 design
decision. Write down the *contract* it must satisfy and decide the mechanism at the keyboard.
